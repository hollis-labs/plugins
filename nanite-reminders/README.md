# Reminders

`nanite.reminders` owns reminder records in its host-supplied DataDir. It adds a
Reminders tab to the working drawer, MCP tools and a context source. It uses only
plugin-sdk, the released public Nanite contract and the Go standard library.

Enable it after restarting older Nanite processes and adopting the matching
host extraction. The host exports the complete `reminders` table and commits a
receipt before dropping that table. The plugin imports only an authenticated,
committed receipt. An export file alone never enables writes. All original IDs,
scopes, project/session references, timestamps, firing state, unrecognized
columns and SQLite storage classes are retained. Missing session references are
preserved rather than discarded. Reconnecting or replaying an import never
resurrects deleted or acknowledged reminders.

## Tools

- `reminders_set`: `text`, `trigger`, optional `scope` (`turn`, `session`,
  `project`). The calling session is authoritative. Project identity is resolved
  from that session, rather than accepted from tool arguments.
- `reminders_list`: optional `offset`, 100 pending visible reminders per page.
- `reminders_ack`: `id`; acknowledges a handled reminder and stops injection.
- `reminders_delete`: `id`; deletes a visible reminder.

Triggers are `{"type":"time","at":"2026-10-03T14:00:00Z"}` or
`{"type":"turn_count","n":2}`. Time reminders become due at or after `at`.
Turn-count reminders use the host's existing session message-count signal. New
reminders store their creation count durably, so reconnects retain the baseline.
Legacy turn-count rows retain the former engine's session-start baseline of
zero because no creation count was stored in the old table. Project reminders
are visible in sessions belonging to the same project; demotion restores the
originating session. `turn` reminders retain their original session provenance
and remain pending until acknowledged, as do session and project reminders.

## Hard breaks

The core `reminder_set` tool, reminder REST routes, Work tab reminder section and
in-process reminder engine are removed by host adoption. Use the plugin tools
and `/api/plugins/nanite.reminders/reminders` routes instead. There are no aliases
or compatibility adapters.

Due reminders repeat in retrieved context until explicitly acknowledged by an
agent or user. Context reads do not mark records fired. Budget omission, failed
retrieval and failed model turns therefore cannot silently consume a reminder.
The drawer can acknowledge or delete reminders before they become due.
Invalid legacy triggers remain stored and visible in the drawer; they do not
produce context. Already-fired legacy records stay fired and are not injected.

The context scope includes all workspace sessions but excludes query text and
keywords. Read-only queries allow only committed exports, session metadata and
usage/message-count accounting. The plugin has no core message-content, SQL,
credential, scheduler or durable-agent mutation access.

## Build and verification

Run `make all` at the repository root. The plugin manifest is generated by
`--manifest`. Publish `reminders/v0.1.0`, verify all four platform archives, then
adopt the released plugin in Nanite before deleting core implementation.
